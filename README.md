# DrawClimateChartWeb · WMO 城市气候统计图网页工具

把命令行工具 `DrawClimateChart` 改造成**网页工具**：在线编辑全部绘图配置、点击即刻出图并在网页右部即时显示、
配置可保存修改或另存（全量 / 继承差量）、支持**临时出图不落盘**。

数据与绘图能力全部来自参考项目（**只读复制**到 `core/`，未做任何修改）：

* 数据源：世界天气信息服务网（WMO）`https://worldweather.wmo.int`
* 绘图：matplotlib（无头 `Agg` 后端），8 种图形类型、双/三轴、单图 / 多图 / 对比图
* 表格：CSV / Markdown / XLSX / JSON
* 配置：YAML，四层来源 + `extends` 继承 + `apply_styles` 命名样式

## 1. 快速开始

**Windows 一键启动**：双击根目录的 `启动服务.bat`。它会自动定位 Python、校验版本、
依赖缺失时自动安装（默认源失败会改用清华镜像重试），启动服务并自动打开网页；
若检测到本工具**已在运行**，则直接打开已有页面，不会重复启动第二个实例。
停止服务：关闭该控制台窗口（或按 Ctrl+C，若提示「终止批处理操作吗」按 `Y`）。

也可以用命令行启动：

```bash
pip install -r requirements.txt
python run.py                 # 启动并自动打开浏览器（http://127.0.0.1:8765/）
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--host 地址` | 监听地址，默认 `127.0.0.1`（仅本机可访问） |
| `--port 端口` | 监听端口，默认 `8765`；**被占用时自动顺延尝试后续 10 个端口** |
| `--no-browser` | 不自动打开浏览器 |

依赖只有参考项目那三个（matplotlib / openpyxl / PyYAML）。
**Web 层只用 Python 标准库**（`http.server` / `json` / `threading` / `urllib`），
前端是原生 HTML / CSS / JS，**没有 npm、没有构建步骤**。

## 2. 界面与用法

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶栏：配置▾ │ 来源/继承 │ ●未保存 │ [不保存] 快捷微调 最终配置 导出模板 缓存 [出图] │
├───────────────────────────────────┬──────────────────────────────────────────┤
│ 左：目标城市 + 配置项（可折叠/搜索）  ║ 右：显示区                                │
│                                       ║                                          │
│   ▲ 中间的分隔条可拖动改宽（左栏限制在窗口宽度的 1/3 ~ 1/2）                      │
│  · 单城/批量 · 对比 · 多图           │  · 图表（缩略条 + 适应宽度 + 另存本地图片） │
│  · cityId 或城市名，逗号分隔          │  · 表格（表格化预览 / 下载）                │
│  · 反查编号 / 查询城市                │  · 运行日志（实时，可筛级别）               │
```

### 2.1 出图

1. 在「目标城市」填 `cityId` 或城市名（逗号分隔，如 `237,北京,香港`）。
2. 选择模式：**单城 / 批量**、**多城市对比**（≥2 城）、**多图（同画布）**（≥2 城，可填 `2x2`）。
3. 点右上角 **出图**。

出图过程中右侧「运行日志」实时显示：提交 → 请求 → 重试 → 限速等待 → 完成（状态码/字节数/耗时）→
绘出要素 → 保存路径 → 请求统计。这是参考项目在 2026-09-20 迭代中专门加入的「请求阶段可见性」能力。

### 2.2 「不保存」开关

| 开关 | 图片 / 表格 | 配置 |
|---|---|---|
| **关**（默认） | 写入 `output/`（按 `output.overwrite` 策略）**且**网页即时显示 | 修改可正常保存 |
| **开**（临时出图） | **不写入本地**，只在内存出图并即时显示；仍可用「另存本地图片」下载 | 修改照旧可保存 |

### 2.3 自动恢复上次使用的配置与左右宽度

**刷新页面 / 重新打开都会自动选中上次用过的配置**，规则如下：

1. 服务端把「上次使用的配置」记录在 `cache/ui_state.json`（切换配置、保存、另存都会更新）；
2. 启动时由**服务端**把结果算好（`GET /api/state` 的 `profile` 字段：上次使用且仍存在 → 否则默认配置），
   前端直接采用并提示「已自动选中上次使用的配置「X」（默认配置为「Y」）」；
3. 若从未记录过、或该配置**已被删除/改名** → 回退到内置默认配置（`profiles.yaml` 的 `default_profile`）；
4. 若该配置**加载失败**（例如文件被改坏）→ 提示原因并回退到默认配置，不影响工具启动。

状态读写失败（文件损坏、无权限、被占用）一律按"没有状态"处理，绝不阻断启动；
清理缓存也不会清掉它（`clear_cache` 只删响应缓存、城市索引与原始响应，且缓存统计不计入该文件）。

**左右分栏宽度**同样会被记住：

* 拖动左/右两栏之间的**分隔条**即可调整宽度（鼠标指针变为 `col-resize`）；
* 左栏严格限制在**窗口宽度的 1/3 ~ 1/2** 之间——拖不出这个范围，窗口缩放时按同一比例重新夹紧；
* 双击分隔条复位（48%），聚焦后按 `←` / `→` 微调（`Shift` 加大步长）；
* 宽度按**窗口宽度**的占比记录，窗口大小不同也保持一致观感；
* 窄屏（< 1080px）自动改为上下排布，分隔条隐藏。

### 2.4 快捷微调

顶栏「快捷微调」支持参考项目 `--mark` 的语法，**只在出图时临时生效**：
不写回上方配置项、不产生「未保存修改」、也不会写入 `config/custom/*.yaml`
（与命令行 `--mark` 语义一致）。

```
hh,r12,t14,p14,tt18     气温轴 +20；降水轴上限 250mm；三处字号
cy / cn                 城市名取短名 / 完整名称
ts5 / rs50              气温轴 / 降水轴刻度步长
r3h / hr3               连写等价于 r3,h（标记之间可省略逗号）
```

* 标记可逗号、空格分隔，也可**连写**：`r3h` = `r3` + `h`、`tt18t14` = `tt18` + `t14`；
  有歧义处（如 `ccy` 会被读成 `cc` + `y`）建议加逗号；

* 登记后按钮显示 `快捷微调 (N)`，标题里列出当前生效的标记；再点弹窗可「清除微调」；
* 微调随每次「出图」下发，作用在**本次出图的配置副本**上；运行日志里逐条打印 `--mark：…`；
* 配置项保持不变，因此「保存修改 / 另存为」写出的仍是未微调的配置；
* 「最终配置」会带上当前微调，方便核对本次实际使用的参数；
* 切换 / 保存配置会清空微调，避免跨配置误用。

## 3. 配置系统

### 3.1 四层来源（沿用参考项目，后者覆盖前者）

1. 内置默认值（`core/config_loader.py::DEFAULTS`）
2. `config/profiles.yaml` 里的命名配置（15 套内置预设）
3. 自定义配置：`config/custom.json` → `config/custom/*.json` → `config/custom.yaml` → `config/custom/*.yaml`
4. 本次出图的临时覆盖（刷新缓存 / 对比元素 / 排列方式 / 表单值）

### 3.2 网页如何保存（内置配置只读）

* **保存修改**：沿用该配置原本的定义方式——原本是 `extends` 差量就继续写差量，否则写全量。
* **另存为** → 二选一：
  * **保存全量配置**：写入解析后的完整配置，可独立于任何配置使用；
  * **继承后仅存修改部分**：写成 `extends: <基线>` + 差异项（基线以后调整，本配置跟着变）。
* 落盘位置统一为 `config/custom/<配置名>.yaml`（单配置裸文件，配置名 = 文件名）。
* **`config/profiles.yaml` 永不被写入**；与内置配置同名时，自定义文件按加载顺序覆盖内置同名配置
  （内置文件本身不变，界面上会明确提示）。

差异项的计算基线由 `core` 自己解析（`resolve_profile` 解析一个只含 `extends`/`apply_styles` 的骨架），
因此继承链与命名样式都不会被本工具重复实现、也不会走样。

### 3.3 按数据类型的输入验证

`app/schema.py` 为全部 462 个配置项声明了**类型 / 枚举 / 范围 / 说明 / 分组**，前端据此渲染控件并即时校验，
后端用同一份规则做权威校验（绕过前端也进不了渲染流程）：

| 数据类型 | 控件 | 校验要点 |
|---|---|---|
| `bool` | 开关 | 只接受 true/false（拒绝 YAML 陷阱里的 `yes`/`on`） |
| `int` / `float` | 数字框 | 整数/浮点、`min`/`max`（如 DPI ≥ 1、透明度 0–1、重试次数 0–20） |
| `int_or_null` / `num_or_null` | 数字框（留空 = 自动） | 允许 `null` |
| `num2` / `num2_or_null` | 两个数字框 | 长度必须为 0 或 2；如 `[12, 6]` |
| `enum` | 下拉 | 值必须在候选内（含数字型枚举如 `pdf_fonttype` 42/3） |
| `color` | 取色器 + 文本框 + 快捷值 | `#RGB(A)`/`#RRGGBB(AA)`、颜色名、`auto`/`none` |
| `template` / `path` | 文本框（列出可用占位符） | 占位符白名单（如 `{city}` `{period}`，文件模板另有限定） |
| `rotation` | 文本框 | 角度数字或 `vertical`/`horizontal` |
| `grid` | 文本框 | `auto` 或「列x行」（`x`/`×`/`✕`/`*`/`,`/`，` 均可，自动归一） |
| `list_enum` | 多选框组 | 取值白名单，允许空数组 = 不输出 |
| `list_str` / `list_color` | 逗号分隔文本 | 逐项校验（颜色逐项验色） |
| `str_map` | 键值表（可增删） | 必须是对象（如 `fetch.headers`、`table.row_labels`） |
| `str_map` + `keyKind=city` / `valueKind=color` | **城市下拉 + 颜色下拉**（专用于「指定城市颜色」） | 键为城市显示名、值为真实颜色 |
| `json` | JSON 编辑框 | 解析失败就地报错（如 `background.bands.seasons`） |

跨字段校验复用 `core.validate_config`（至少启用一个绘图元素、单位一致性、副轴与元素冲突、
`multi.grid` 格式等），另有两条补充告警：`fill_between` 的边界元素不可识别、扩展键说明。

> 两个**扩展键**：`axes_x.label_text` 与 `compare.color_map` 被 `core` 的绘图代码读取，
> 但未列入 `DEFAULTS`。本工具把它们放进表单并精确剔除对应的「未知配置项」告警。

### 3.4 「指定城市颜色」（`compare.color_map`）怎么用

| 要点 | 说明 |
|---|---|
| 生效范围 | **只在「多城市对比」模式下生效**；单城 / 批量与多图模式完全不读它 |
| 为什么要它 | 对比配色默认按 **排序后位置** 轮询（`sort_by` 默认按数值降序），因此换对比元素、增删城市、城市数超过配色序列长度时，同一城市的颜色都会变。手动指定可把城市"钉死"在一个颜色上 |
| 键 | **城市显示名**（受 `data.city_short_name` 影响），不是 cityId。网页端给出**下拉候选**（来自实际解析出的城市），避免手输出错 |
| 值 | 颜色：下拉里有 18 个预设（前 8 个就是 `compare.colors` 的默认序列），也可用取色器或直接填 HEX |
| 一键钉色 | 「按当前对比城市一键钉色」按钮会给本次对比的每个城市各分配一个固定色（优先用当前「城市配色序列」） |
| 不生效的情形 | `compare.color_by = city_id` 时本表**完全不生效**（core 直接按 `colors[cityId % 长度]` 取色），网页端会就地提示 |
| 键写错的后果 | core 会**静默**退回轮询色；网页端在对比模式下会就地标出「不在本次对比城市中」，但**只告警、不阻断出图** |

**模式感知校验**：以上关于 `compare.color_map` 的检查**只在“本次出图是多城市对比”时进行**，
其余模式（单城 / 批量、多图）一律忽略它——既不校验、也不提示，配置可正常加载与出图。

### 3.5 脏检查与提示

任何配置项变更后顶栏出现「● N 项修改未保存」。切换配置 / 出图 / 关闭页面时会弹出：

```
[取消] [放弃修改] [另存为…] [保存修改]
```

## 5. HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/schema` | 配置 Schema（类型/枚举/范围/说明/分组） |
| `GET` | `/api/state` | 界面状态：上次使用的配置 + 默认配置 + 可用清单 |
| `POST` | `/api/state` | 记住上次使用的配置（`{"lastProfile": "名称"}`，空串 = 清除） |
| `GET` | `/api/profiles` | 配置清单（名称/说明/来源/是否内置/是否覆盖内置） |
| `GET` | `/api/profiles/<名称>` | 解析后的表单值 + 继承信息 + 未知键 |
| `POST` | `/api/profiles/validate` | 逐字段校验 + 跨字段校验 |
| `POST` | `/api/profiles/save` | 保存修改（`keep`）/ 全量（`full`）/ 继承差量（`extends`） |
| `POST` | `/api/profiles/delete` | 删除网页保存的自定义配置 |
| `POST` | `/api/profiles/marks` | 快捷微调**预览**（`--mark` 语法；只回变更说明/告警，不改配置） |
| `POST` | `/api/profiles/text` | 查看最终配置 / 导出全量模板 |
| `GET` | `/api/cities` | 城市查询（关键词 / 国家 / 条数） |
| `GET` | `/api/cities?resolve=237,北京` | 逐项解析 cityId / 城市名 → 含**显示名**（`color_map` 的键候选） |
| `POST` | `/api/render` | 提交渲染任务 |
| `GET` | `/api/render/<任务>?cursor=N&wait=20` | 任务快照（长轮询） |
| `GET` | `/api/render/<任务>/events` | 实时日志流（SSE） |
| `GET` | `/api/render/<任务>/artifact/<产物>` | 图片/表格字节流（`?download=1` 下载） |
| `POST` | `/api/render/<任务>/cancel` | 取消任务 |
| `GET` | `/api/cache` ・ `POST /api/cache/clear` | 缓存统计 / 清理 |

## 6. 关键设计说明

* **一次渲染、两种去向**：`core/chart.py::_save()` 只依赖 `path.suffix` 与 `fig.savefig(path, …)`，
  而 matplotlib 原生支持文件类对象。因此 `app/rendering.BufferTarget`（带 `suffix` 的内存缓冲）
  可以与真实 `Path` 混在同一个 targets 列表里——**同一张图既落盘又进内存预览，绝不重复建图**。
  这也是 `core/` 能保持零修改的原因。
* **渲染串行**：matplotlib 非线程安全，所有渲染都在全局 `_RENDER_LOCK` 内执行；任务可并发提交、串行出图。
* **实时日志**：优先用 SSE（分块传输）；浏览器不支持或连接中断时自动退回 `?cursor=N&wait=20` 长轮询。
* **网页预览始终是 PNG**：`output.chart_formats` 只决定**落盘**格式；显示区始终另渲染一张 PNG，
  以免「配置里没勾 png」就看不了图。表格预览用 `output.table_formats`（XLSX 不支持网页预览，仅可下载）。
* **缓存**：完全沿用参考项目的 HTTP 响应缓存（`SHA1(URL)` 命名、TTL）与城市索引缓存；
  界面提供「忽略缓存强制重新请求」与缓存清理。命中缓存不发请求、也不占限速额度。

## 8. 已知限制

* 数据源只提供**月气候平均值**（气候态），不含逐年历史序列；平均气温由 `(最高+最低)/2` 派生。
* 约 30% 的 WMO 城市没有气候数据，会在结果里标记为「失败」并给出原因，不影响其他城市。
* 多图（同画布）**只出合并图、不出表格**；量程按行统一，跨行不可直接比高低。
* XLSX 表格不能在网页里预览（二进制格式），只能下载。
* 单进程内存态任务仓库保留最近 40 个任务，产物保存在内存里，重启后需要重新出图。
* 「上次使用的配置」与「左右分栏宽度」记录在服务端的 `cache/ui_state.json`
  （同一台机器、所有浏览器共用）；它们只是便利性状态，
  删掉或损坏只会回到默认配置 / 默认宽度，不影响任何功能。
* 参考项目 `core/` 中的两个键（`axes_x.label_text`、`compare.color_map`）未列入其默认值表；
  本工具按扩展项处理，配置文件中出现它们时不会报「未知项」告警。
* `compare.color_map` 的键是**城市显示名**（core 的既定行为）：既受 `data.city_short_name`
  影响，也不能写 cityId。网页端用「按 cityId / 城市名解析出的显示名下拉」来规避手输错误；
  若你把「城市名取短名」从关闭改为开启，已有的键需要同步改成短名。
* 保存/另存只写**真正的修改**：运行时的 `profile_description` 与空值的扩展键都不会写入配置文件。
  历史文件里若已存在这类噪音，下次「保存修改」会自动把它重写干净。
